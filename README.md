# jiodayo のブログ

https://jiodayo.github.io/blog/

Astro で作った静的サイト。`main` に push すると GitHub Actions が
ビルドして GitHub Pages に公開する。

ルートの `jiodayo.github.io` には別のサイト（合言葉つきの日記）が動いているため、
このブログは `blog` リポジトリに置き、URL に `/blog/` が挟まる形にしている。
そのため `astro.config.mjs` に `base: '/blog'` を設定してある。

## 日常の使い方

```bash
npm run dev      # http://localhost:4321 で確認しながら書く
npm run build    # dist/ に本番ビルド（公開前の確認用）
npm run preview  # ビルド結果をローカルで表示
```

## 記事を書く（エディタを使う）

`ブログを書く.command` を Finder からダブルクリックする。
エディタと Astro の dev サーバーが立ち上がり、ブラウザまで開く。
終了するときは、開いたターミナルのウィンドウで `Ctrl+C`。

よく使うなら、このファイルを Dock かデスクトップにエイリアスとして置いておくとよい。

ターミナルから起動してもよい。

```bash
npm run editor
```

どちらでも http://127.0.0.1:4322 が編集画面になる。

- 左が記事一覧、真ん中が編集、右が**実際のサイトの見た目**のプレビュー
- 入力は自動保存される（保存ボタンはない。⌘S で即保存）
- 画像はエディタに**貼り付け／ドラッグ&ドロップ**で入る。`src/content/blog/images/` に
  保存され、ビルド時に WebP へ自動変換される
- 横幅 1600px を超える画像は、保存する前に 1600px へ縮小される。
  本文の表示幅は 720px なので、スマホの写真（4000px 超）をそのまま入れると
  リポジトリが無駄に重くなるため。縮小したときはツールバーの下に結果が出る
- タグはカンマ区切りで入れる。入力欄の下に、他の記事で使ったタグが並ぶので
  クリックでも付け外しできる（綴りが揺れると別のタグになってしまうため）
- 記事ごとに**ヘッダ画像**を付けられる。本文の先頭に大きく出る
- **URL を埋め込める**（ツールバーの「埋め込み」か ⌘⇧K）。本文に URL を貼ったときも
  「埋め込みにする」が出る
  - YouTube → 動画の埋め込み（Cookie を置かない nocookie 版）
  - X → 本文つきの引用
  - そのほか → OGP を読んだリンクカード。画像は手元に落として縮小する
  - 外部のスクリプトは一切読み込まない。表示が他所の都合で壊れないようにするため
- **テンプレート**から、脚注・折りたたみ・補足のボックス・図と説明文・表などを入れられる。
  脚注は本文の番号と末尾の定義を同時に作り、番号は自動で次に進む
- 左上の検索で記事を絞り込める。本文の下に文字数と行数が出る
- 「公開する」を押すと、**何が送られるのか一覧**が出る。送ったあとは GitHub の
  ビルドを見ていて、終わると右上に「サイトに反映されました」と出る
- 下書きのまま「公開する」を押すと確認が出る。
  下書きはコミットされても公開サイトには出ないため
- 「下書き」にチェックを入れている間は公開サイトに出ない。プレビューには出る
- 「公開する」ボタンで `git add` → `commit` → `push` まで実行する
- 上の「サイト設定」から、サイト名・説明・トップの一行・トップの見出し画像・リンクを変えられる
- 上の「画像」から、どの画像がどの記事で使われているかを見て、
  どこからも使われていないものをまとめて消せる
- 左下の「ページ」から About を記事と同じように編集できる

エディタはこのMacの中だけで動く（127.0.0.1 にしかバインドしない）。

## VS Code で書く

`tools/vscode-blog/` に、このブログ用の VS Code 拡張を置いてある。
Web のエディタの代わりに VS Code で書きたいときはこちら。

```bash
tools/vscode-blog/install.sh
```

入れたあと、VS Code で `⇧⌘P` → `Developer: Reload Window`。
コマンドパレットで「ブログ」と打つと次が出る。

| コマンド | 内容 |
| --- | --- |
| ブログ: 新しい記事 | スラッグと frontmatter を作って開く |
| ブログ: 公開する | 保存 → `git add -A` → commit → push |
| ブログ: プレビューを開く | dev サーバーを起動して、その記事を横に表示 |
| ブログ: 画像を挿入 | ファイルを選んで挿入 |
| ブログ: 下書きを切り替える | `draft: true` の付け外し |

画像は**貼り付け／ドロップ**でも入る。Web のエディタと同じく 1600px に縮小される
（こちらは macOS 標準の `sips` を使う）。`tags:` の行ではタグが補完される。
右下に未公開の変更の件数が出て、クリックで公開できる。

拡張を直したときは `install.sh` を実行し直すこと。

**Web のエディタと同時に同じ記事を開かないこと。** あちらは自動保存するので、
VS Code 側で書いた内容を上書きすることがある。どちらかに寄せて使う。

### 記事を直接書く場合



`src/content/blog/` に `.md` ファイルを作る。ファイル名が URL になる。

```markdown
---
title: '記事のタイトル'
description: '一覧とSNSカードに出る短い説明'
pubDate: '2026-10-30'
tags: ['日記', 'メモ']
---

本文。見出しは ## から使う。
```

`tags` は省略してよい。`updatedDate: '2026-11-05'` を足すと「最終更新」が表示される。

書いたら push すれば1〜2分で公開される。

## サイドバー（アーカイブとタグ）

本文の右に、投稿した年月とタグの一覧が出る。中身は記事から毎回組み立てるので、
記事を増やしても手で直す場所はない。画面が狭いときは本文の下に回り込む。

| URL | 内容 |
| --- | --- |
| `/archive/` | 全記事を年→月で並べる |
| `/archive/2026/` | その年の記事 |
| `/archive/2026/10/` | その月の記事 |
| `/tags/` | 使っているタグの一覧 |
| `/tags/<タグ名>/` | そのタグの記事 |

日本語のタグはそのまま URL に入る（`/tags/日記/`）。リンク側では自動でエスケープされる。

## 画像の置き場所が2つある理由

| 入れかた | 保存先 | Astro の最適化 |
| --- | --- | --- |
| 記事の本文に貼る・ドロップする | `src/content/blog/images/` | される（WebP に変換） |
| About などのページに貼る | `src/content/pages/images/` | される |
| 埋め込みのカード、テンプレートの「図と説明文」 | `public/embeds/` | されない |

Markdown の `./images/` は「その `.md` があるフォルダ」から解決されるので、
記事とページで画像の置き場所が分かれる。エディタは開いているものに合わせて振り分ける。

Astro が面倒を見るのは Markdown の `![]()` だけで、生の HTML の中の `<img>` は
そのまま出力される。記事からの相対パスのままだと記事ページの下を探しに行って 404 になるため、
生の HTML から参照する画像は `public/` に置いて絶対パスで書いている。
どちらも保存するときに 1600px へ縮小される。

| `src/layouts/BlogPost.astro` | 記事ページの枠組み |
| `src/layouts/Page.astro` | 記事以外のページの枠組み（本文＋サイドバー） |
| `src/components/Sidebar.astro` | 右のアーカイブとタグ |

## 初回だけ必要な設定

すでに設定済み。作り直すときの手順として残しておく。

1. GitHub で `blog` という名前のリポジトリを作る。
2. push する。
3. リポジトリの **Settings → Pages → Build and deployment → Source** を
   **GitHub Actions** にする。これを忘れると公開されない。

### リポジトリ名を変えた場合

URL は `https://jiodayo.github.io/<リポジトリ名>/` になるので、
`astro.config.mjs` の `base` を同じ名前に書き換える。

サイト内のリンクはすべて `src/lib/url.ts` の `url()` を通しているので、
`base` を変えれば全部追従する。ベタ書きの `href="/..."` は足さないこと。

## 独自ドメインに移すとき

独自ドメインは無料アカウントでも使える（GitHub Pro は不要）。
ドメイン自体はレジストラで取得する。

1. `astro.config.mjs` の `site` を `'https://example.com'` に書き換え、
   **`base: '/blog'` の行を削除する**（独自ドメインならサブパスは不要）。
2. `public/CNAME` を作り、ドメイン名だけを1行書く（`https://` やスラッシュは付けない）。

   ```
   example.com
   ```

3. DNS を設定する。
   - サブドメイン（`www.example.com` など）の場合は
     CNAME レコードを `jiodayo.github.io` に向ける。
   - ルートドメイン（`example.com`）の場合は A レコードを4つ登録する。
     ```
     185.199.108.153
     185.199.109.153
     185.199.110.153
     185.199.111.153
     ```
     （最新の IP は GitHub のドキュメントで確認すること）
4. リポジトリの **Settings → Pages → Custom domain** にドメインを入れ、
   DNS が通ったら **Enforce HTTPS** にチェックを入れる。

DNS の反映には数分〜数時間かかることがある。
